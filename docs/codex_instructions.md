# codex_instructions.md

## 1. このファイルの目的
Codexが今後このUnityプロジェクトで迷わず開発を進めるための、実装順序と判断基準を明確化する。

## 2. 開発進行の基本方針
1. まずJSON仕様と読み込み基盤を作る（データ駆動の土台）。
2. 次に状態モデル（GameState）を作る。
3. その後にUI・演出を重ねる。

## 3. 推奨タスク分割
### Phase 1: データ層
- StageData DTO定義
- StageLoader（JSON読み込み）
- StageValidator（整合性チェック）

### Phase 2: ロジック層
- エンティティ位置管理
- 移動可否判定
- 条件違反判定
- 手数カウントと最短手数比較

### Phase 3: プレゼンテーション層
- シーン上のロケーション表示
- エンティティ表示
- 入力UI（搭乗者選択、ルート選択）
- 結果表示（クリア/失敗）

## 4. 実装時の制約
- 本格実装前に、`docs/stage_data_design.md`との整合性を優先する。
- 仕様に曖昧さがある場合は、独断で進めず選択肢を提示する。
- Unity自動生成ファイルの不要編集は避ける。

## 5. 完了報告テンプレート
- 変更ファイル一覧
- 追加/変更したクラスの役割
- 確認方法（Unity Editor操作手順、必要ならコマンド）
- 未確定事項（次の意思決定が必要な点）
